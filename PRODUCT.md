# Talents Product Design

## Product Strategy

Talents is a bilingual Arabic-first marketplace connecting brands with creators, influencers, models, photographers, videographers, hosts, and other campaign-ready talent.

The landing page should convert three visitor types:

- Brands that need to discover and book reliable talent quickly.
- Talents that want a credible profile and better inbound opportunities.
- Agencies or marketing teams comparing options before publishing a brief.

The first screen must establish trust immediately: real media, clear search, strong CTAs, proof metrics, and a sense that the marketplace is active.

## Brand Identity

The visual direction is premium, cinematic, and marketplace-focused. The brand should feel closer to a professional booking platform than a generic portfolio directory.

Core personality:

- Professional, not playful.
- Premium, not flashy.
- Minimal, but not empty.
- Trustworthy, with visible proof.
- Arabic-first, with English support.

The current palette centers on charcoal surfaces, restrained neutral backgrounds, gold for premium emphasis, and teal for trustworthy action.

## Landing Page Philosophy

The landing page is designed as a full product narrative:

1. Hero: make the promise and search action obvious.
2. Categories: help users self-select quickly.
3. Featured talents: show quality and booking evidence.
4. How it works: explain brand and talent paths.
5. Campaign moments: prove the platform supports real work.
6. Features: explain why the marketplace is operationally useful.
7. Testimonials: add human trust.
8. Pricing preview: frame value without building billing yet.
9. FAQ: remove conversion doubts.
10. Final CTA: close with one clear next step.

## UX Improvements

- Stronger first impression through cinematic creator-production imagery.
- Better conversion path through a large search control and clear CTAs.
- More trustworthy talent cards with image, rating, price, portfolio preview, and verification.
- Reduced visual inconsistency by introducing semantic theme tokens.
- Cleaner maintenance model by moving landing content into one editable file.
- Responsive layout designed for desktop, tablet, and mobile.
- Accessible structure using semantic sections, search role, labeled inputs, keyboard-friendly links, and native FAQ details.

## Implementation Boundaries

This redesign does not change:

- Authentication behavior.
- Supabase data fetching.
- Booking implementation.
- Payment implementation.
- Admin flows.
- Marketplace API routes.

It only changes the global visual foundation and the public home landing experience.
